# Tracepoint Ethereum evaluation — second pilot

## Local dataset setup and publication policy

The public repository does **not** redistribute the source or address-level derivatives of **ERC-20 Auxiliary Data**, authored by **Shahar Somin**, [Harvard Dataverse DOI 10.7910/DVN/MBF0GC](https://doi.org/10.7910/DVN/MBF0GC). File-level redistribution rights for `labeled_addresses__enriched.csv` were not independently verified. Obtain that file yourself from the original publisher and place it at `backend/evaluation/raw/labeled_addresses__enriched.csv`. Tracepoint does not redistribute the source dataset.

From `backend/`, verify the source file's SHA-256 against the checksum recorded below, then generate the local split and optional operational label file:

```sh
shasum -a 256 evaluation/raw/labeled_addresses__enriched.csv
python evaluation/split_labels.py
```

The split script writes `evaluation/label_split.json`, `evaluation/label_conflicts.json`, and `data/labels/ethereum_public_cex.json` locally. These files, discovery/case manifests, per-case results, address-level dataset-quality files, raw inputs, and API caches are Git-ignored. The application runs without the optional public-label file, using its independently curated labels and synthetic demo fixtures. To construct a **new** local candidate pool, configure a GoldRush key in ignored `backend/.env` and run `python evaluation/build_real_cases.py --limit 220 --max-probes 370 --pilot-size 20`. This uses live bounded provider data and is not an exact replay of the historical freeze.

The public repository retains evaluation code, methodology, checksums, aggregate metrics and failure analysis, tests, and synthetic fixture results. The historical 150-case manifest and per-case predictions are excluded. `evaluate_final.py` checks their original hashes and Git reference; a new commit cannot rerun that exact frozen evaluation from public files alone. Locally retained excluded artifacts and the recorded pre-commit Git state are required for an exact replay. Do not overwrite the preserved aggregate historical results when running a new evaluation.

Aggregate results from the original 15-case baseline are preserved in `pilot1/`; its address-level case files are excluded from the public commit. The second pilot tests a corrected production GoldRush adapter and a frozen operational/held-out split of public VASP endpoint assertions. It is **not** the final 100–150-case benchmark.

Input: Somin, *ERC-20 Auxiliary Data*, `labeled_addresses__enriched.csv` ([Harvard Dataverse DOI](https://doi.org/10.7910/DVN/MBF0GC)); SHA-256 `579b42862499032390ea519da5aca00470643ca1c06bdd392f39c9af55e71157`. The ignored raw file has 10,627 rows and 370 distinct CEX endpoints across 16 entities. This is a published Etherscan-derived assertion set, not independent proof of endpoint ownership. Its publication year is 2025; it does not provide per-address observation dates, FIU status, or numeric confidence/reliability.

`split_labels.py` deterministically holds out approximately 30% per entity using seed `2612026`, retaining curated overlaps in the operational group and at least one non-curated operational endpoint per entity. `label_split.json` records **every** address, entity, stratum, curated overlap and dataset service URL. `ethereum_public_cex.json` adds only operational non-curated addresses to the app; the loader gives original curated labels priority. Each public label carries the DOI `source_url`, source statement and normalized address. Unavailable confidence, reliability, observation date and FIU status remain null. The engine's pre-existing quality cap treats absent numeric quality as zero; this is an explicit conservative policy for missing assurance, not a measured probability or changed weight. Held-out addresses are never loaded as operational labels. Known-endpoint performance measures tracing and recognition given published intelligence; held-out outcomes measure coverage limits, not ML generalization. The source dataset and curated Etherscan labels have related provenance, so this is not independently audited ownership ground truth.

`split_counts.json` records per-entity group sizes. `label_conflicts.json` records two addresses where the public entity assertion disagrees with a curated label (public OKX versus curated Bybit; public Bittrex versus curated OKX). The second-pilot case and outcome involving the latter remains visible and is not retroactively replaced. These addresses cannot be uncontested single-label ground truth for a final benchmark; a final frozen selection rule must exclude both conflicts before final cases are chosen, with exclusions reported.

For historical methodology only, the phase-2 commands were run from `backend/` with ignored `.env` configured. **Do not run them in the benchmark checkout:** they write local case/result files. Use an isolated copy when conducting a new evaluation.

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B evaluation/split_labels.py
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B evaluation/build_real_cases.py --limit 220 --max-probes 370 --pilot-size 20
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B evaluation/evaluate_real.py
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B evaluation/evaluate_fixtures.py
```

The builder orders endpoint probes round-robin by entity and stratum, and picks the most recent qualifying inbound transfer in the observed GoldRush page. Sources must be distinct, not any published CEX endpoint or an existing operational VASP endpoint, not zero address, and not a first-pilot source. It keeps at most one case per endpoint and source. `case_pool.csv` retains all constructed candidates; `real_cases.csv` is a predeclared 70/30 operational/held-out, entity-round-robin 20-case sample, selected before running predictions. A direct case has an observed source → published endpoint transaction hash, block and time; this establishes a transfer, not sender ownership. Cases are not replaced after failure. The first-pilot cases, errors and metrics remain untouched in `pilot1/`.

The evaluator uses the production provider, loader, request model and engine. It checks the exact expected transfer in the retrieved source evidence. A case with multiple directly observed VASP entities is visible but excluded from the single-label accuracy denominator. Missing expected edges remain in attempted and retrieval denominators. `results.csv` holds every attempted case, including errors and exclusions. Conditional top-1/top-3 and direct-hop accuracy use only unambiguous cases with retrieved expected evidence; the known and held-out strata are reported separately. Hop MAE uses only predicted paths to the expected entity and states that denominator. Nearest-VASP accuracy is **not** calculated: one observed direct edge cannot prove global nearest service across complete history. Real-world specificity, precision, recall and F1 are not measured because independently verified negative ground truth is unavailable. The five controlled fixtures are kept separate.

GoldRush `transactions_v3/` now begins at the most recent page and walks back at most four earlier pages. It reads native value and decoded token Transfer logs. The invalid unfiltered `transfers_v2` call has been removed because the live API requires `contract-address`; 400 errors are not retried. This remains a bounded recent history, so missed older transfers are expected and visible. `cache/` stores only public response data, reuses it by path/parameters, and has separate resumable second-pilot progress keyed to dataset, split and provider hashes. Raw data and cache are Git-ignored. Request-wrapper calls and cache hits are recorded; retries inside HTTP calls can make wire attempts higher. No credentials enter output files.

The second pilot is a method check, not a statistically representative Ethereum sample. The builder begins from published CEX endpoints, so results do not describe arbitrary wallets. Scores are uncalibrated evidence scores. A VASP association does not establish wallet ownership or criminal liability. The final benchmark requires explicit approval and a frozen configuration after this pilot.

## Final frozen benchmark procedure

`pilot2/` preserves the second-pilot manifest, candidate pool, results, metrics and reports. The final methodology is recorded in `benchmark_freeze.json` before the final predictions. It locks the dataset, split, label files, conflict rule, seed, eligibility, sampling method, attribution weights, thresholds, GoldRush bounds, code hashes, Git reference and evaluator configuration. Once discovery creates a pool of at least 100 cases, `select_final_cases.py` selects up to 150 cases deterministically and records checksums for both `case_pool.csv` and `final_cases.csv` in the freeze file. If fewer than 100 legitimate candidates exist, selection stops without predicting. `evaluate_final.py` refuses to run if the frozen cases, dataset, labels, provider, engine, selector or evaluator differ from the recorded hashes.

The two contradictory addresses in `label_conflicts.json` retain both published and curated labels with their URLs. A selected conflicting endpoint receives `ground_truth_conflict` and is excluded from conditional single-label accuracy while remaining in attempted and retrieval denominators. Similarly, ambiguous direct multi-VASP sources remain visible and excluded only from conditional single-label accuracy. Expected-transfer misses, provider failures and analysis failures remain explicit statuses. Operational known-endpoint metrics use only unambiguous, conflict-free cases with the exact expected edge retrieved. All-case retrieval, evaluable rate and end-to-end success use every fixed attempt. Held-out findings are separate and do not imply unknown-endpoint recognition.

After final evaluation, `summarize_final.py` renders the SIH report and presentation summaries from the immutable results. It never changes predictions. Full case-level outputs remain in `results.csv`; the original pilots stay in their archives. No real-world specificity, precision, recall, F1 or global nearest-VASP accuracy is computed without suitable independent ground truth.

After the final run, `real_cases.csv` remains the second-pilot manifest for compatibility with the pilot evaluator; `final_cases.csv` is the only final-benchmark manifest. `results.csv`, `metrics.json`, and `dataset_quality.json` are the final benchmark outputs. Their pilot-2 versions are retained under `pilot2/`.

The source article describes the auxiliary file as public data, but its exact dataset-specific redistribution terms were not independently verified. The source CSV, derived address-level files, and GoldRush response cache therefore remain outside the public commit.
